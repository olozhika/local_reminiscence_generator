## 核心功能

- **智能总结**：利用大语言模型（LLM）将零散的对话整合为具有叙述性的事件。
- **记忆提取**：自动识别并更新人物、地点、概念等“记忆节点”，支持增量更新。
- **多日期识别**：自动从聊天记录的时间戳中识别日期，支持跨日期的长文本一次性处理。
- **智能分批**：支持超长聊天记录，根据对话停顿（默认3小时）或文件边界自动切分批次，确保不超出模型上下文限制。
- **群聊脱水**：针对群聊文件，可仅保留目标用户及其前后的上下文，大幅节省 Token 并提高总结质量。
- **时间范围过滤**：支持指定起始和截至日期，自动剔除范围外的无效信息。
- **Astrbot 兼容**：生成的数据库结构与 Astrbot 插件[本地回忆[APLR]](https://github.com/olozhika/astrbot_plugin_local_reminiscence) 完全一致，可直接替换使用。

## 工作流程

1. **配置加载**：读取 `config.json` 中的 API 密钥、模型及处理参数。
2. **日期过滤**：根据设定的 `start_date` 和 `end_date` 裁剪所有原始 `.txt` 文件。
3. **群聊预处理**：对文件名含“群聊”的文件进行脱水，仅保留目标用户相关的对话片段。
4. **Token 估算**：统计处理后的总字符数，给出预计 Token 消耗范围并请求用户确认。
5. **分批总结**：将文本切分为合理大小的批次，循环调用 LLM 进行总结。
6. **数据持久化**：将生成的事件和节点信息存入 SQLite 数据库。

```bash

```

在项目根目录下创建 `chat_records` 文件夹，将您的聊天txt记录复制放入其中（请务必在其他地方保存你准备的这些聊天记录，因为本程序会在预处理阶段删掉其中部分冗余内容）。


## 注意事项

- **数据覆盖**：预处理步骤（日期过滤和群聊脱水）会**直接修改并覆盖** `input_dir` 下的原始文件，请务必提前备份您的原始聊天记录。
- **Token 消耗**：总结大量聊天记录会消耗较多 Token，请关注程序启动时的估算信息。（没错，有预估，在你没输入yes之前是不会调用LLM的，所以放心试）
- **API 兼容性**：支持所有兼容 OpenAI 接口标准的模型（如 DeepSeek, 智谱 AI, 月之暗面等）。

## 数据库说明

生成的数据库包含以下核心表：
- `events`: 存储总结后的事件叙述、情绪、重要性等。
- `nodes`: 存储提取的实体/概念及其描述。
- `tags` & `event_tags`: 存储事件关联的标签。
- `daily_reflections`: 保持兼容性的空表。
- `event_relations`: 存储事件间的逻辑关系。
